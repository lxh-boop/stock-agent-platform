# 策略研究：一次性破坏式迁移

本次将 `lxh-boop/Strategy` 回测相关业务迁入现有 Python/React/PostgreSQL 平台，不增加 Node 后端、MySQL、DuckDB、DolphinDB 或新的账号系统。参考源提交 `3186e1209c176953330f128155ee09c285ddf4af`；迁移采用 Python 重写而非逐行复制，修正的行为以下列契约为准。没有分阶段入口、旧格式适配器或假数据回退。

## 唯一运行链路

`页面 / Agent → 严格规格校验 → BacktestService → 本人数据快照 → 同一研究内核 → 本人持久报告`

三种运行类型共用取数、任务、用户隔离和报告接口：

| 功能 | 本版实现 |
| --- | --- |
| 定期调仓 | 每N个数据交易日调仓，过滤、排序、方向、持仓数、目标仓位、费用与滑点 |
| 条件触发 | 间隔=0；至少一条入场条件；每天判断信号、仓位偏离带与退出 |
| 权重 | 固定因子权重 / 滚动正 Rank IC；仅用已兑现的一日收益，无正IC回退等权并记录实际值 |
| 仓位 | 按名额等权 / 按排名固定比例 / 指定因子正值比例；未分配比例留现金 |
| 退出与保护 | 字段卖出、止盈、止损、持仓峰值回撤、最长持有日、排名跌出、不卖条件 |
| 指数与择时 | 本人Tushare的沪深300/中证500/上证指数真实行情；指数入场过滤、1～3条投票、牛熊滞回与熊市仓位 |

## 数据和权限

- Token仍在原账户表，Alpha158仍保留五年；本人第一次写入自动建立 `stock_ud_<哈希>.backtest_run`、`backtest_strategy`，需要指数时建立 `backtest_index_cache`。不删除账号、持仓、订单或其他用户数据。
- 读取个人Alpha158的指定列、指定日期/代码，服务端游标按天流式处理；整个任务使用 PostgreSQL REPEATABLE READ 只读快照，运行中日更/清理不会改变输入。
- 单次最多10因子、1000股票、1300数据交易日、50持仓、20000笔成交。Page与Agent共享本人执行锁；后台提交还有请求UUID幂等和同用户活动任务限制。
- 报告记录完整参数、引擎/因子版本、实际输入指纹和指数来源。保存成功报告后不会被重跑同一UUID覆盖；失败/取消只在Task Runtime留状态，不保存半份成功报告。
- 明细分页在数据库完成，前端不能指定owner/schema/Token。已完成报告独立于五年因子清理，过期数据不能承诺可原样重跑。
- 指数请求只用本人Token；缺权限、额度、交易日或行情报错，不用零收益/其他用户数据替代。指数缓存按请求范围复用，扩大范围重新校验。
- Alpha158以外财务/行业MySQL表不在此平台，不能假装已迁入这些数据。历史行业或指数成员请先提供带日期的真实成员快照；没有快照时明确使用个人库股票范围，存在幸存者偏差。

## 计算口径与有意修正

- T日收盘信号T+1开盘/收盘执行；不提供使用当日收盘因子又按当日收盘成交的前视模式。末日信号不成交，期末不强制平仓。
- 平均秩百分位、稳定代码打破并列；缺因子剔除该股，全截面缺因子不误判为清仓。
- 所有交易共用费用、现金、可卖数量、100股买入整手和可选固定涨跌幅校验。先卖后买；当日新增数量锁定，补仓不锁住原有可卖持仓。
- 退出缺行情时保留指令重试，买入缺行情不追单；旧价估值标记stale，不宣称数据缺失就是停牌。
- 不卖条件占用名额并阻止单股退出；组合择时降仓优先。固定仓位总和>1归一化，<1且已填足名额时留现金；因子仓位全非正则不买。
- 暂停区间仍按市场估值，删除原仓库冻结净值的特殊口径。
- 原始OHLC配合adj_factor；复权变化按等效份额再投资近似处理，非实际分红送转到账，可能产生小数持仓。综合买卖费率是用户假设，不声称等于历年全部真实税费。
- 可选固定比例限制不是按板块/ST/新股区分的真实涨跌停；未模拟冲击、成交量参与率或退市清算。缺整个市场交易日需数据源进一步核验，不静默宣称交易所完整撮合。
- 同池等权基准为前一数据日已知成员的复权收益参考（非实际交易基金），缺个股行情沿用旧价；真实指数基准必须有数据。年化252日、无风险率0、胜率区分卖出笔与正收益日。
- 因子分析收益为收盘到下一采样收盘、等权不计费用；多空研究序列不代表可交易账户。IC/相关性缺值成对剔除，不足3只或零方差为空；IR为IC均值/样本标准差、不年化；相关矩阵按方向调整后的因子计算。

## 接口与布局

`GET /api/v1/web/backtests/catalog` → 可用字段、日期、指数和规格JSON Schema。
`POST /api/v1/web/backtests`、`/analyses`、`/screen` → `{spec, request_id, confirmed:true}`，返回Task。
`GET /api/v1/web/backtests` → 本人报告；`/{uuid}`摘要、`/{uuid}/rows`数据库分页、`/{uuid}/export`全报告；DELETE需确认。
`GET/PUT /api/v1/web/backtests/strategies` 与 DELETE `/strategies/{uuid}` → 本人策略库。

`backtesting/`仅 contracts、signals、engine、analysis、market、store 六个职责模块；不引入通用插件框架。前端保留一个“策略研究”页面，三个任务标签和一套历史/报告，不再新增独立站点。
