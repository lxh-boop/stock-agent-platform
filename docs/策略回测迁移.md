# Strategy 策略工作台与 Agent 工具整合

将 [lxh-boop/Strategy](https://github.com/lxh-boop/Strategy/tree/3186e1209c176953330f128155ee09c285ddf4af) 的策略工作台与研究工具整合到现有 Python/React/PostgreSQL 平台。源提交为 `3186e1209c176953330f128155ee09c285ddf4af`；原有研究内核继续复用，界面、存储和工具按当前平台契约实现，不增加第二套 Node 后端、MySQL、登录或 Agent 引擎。

## 使用流程

- 主导航“策略”进入 `/strategies`，展示本人保存的策略、真实运行状态和最近成功回测。原 `/paper-trading` 链接转到此页；原模拟账户保留在 `/paper-account` 二级入口，资金、持仓、流水、画像和日更绑定不改动。
- “新建策略”填写研究需求后跳到 AI Agent 预填草稿，由用户检查并发送。研究工具先查询本人数据覆盖范围，经批准后提交后台任务，完成后读取报告，再从报告保存到“我的策略”。也可从页面进入研究表单直接编辑参数。
- 策略配置有版本，报告按策略 ID 与版本关联，不能用相同名称猜测归属。修改参数不把旧业绩冒充新版本业绩；重新回测失败仍保留上次成功报告并显示本次失败状态。
- 报告提供净值、基准、回测持仓、成交、动态因子权重与失败订单原因。原仓库的示例持仓、内存存储兜底和模拟收益不进入生产。
- 删除策略只删除研究策略定义，保留独立报告及原模拟账户记录。研究策略的保存和重跑不会自动启用旧模拟盘执行器。

## 源工具与当前数据的对应

| 源工具 | 平台能力 |
| --- | --- |
| `list_factor_tables` / `list_factor_fields` / `read_factor_data` | 查询本人实际可读数据集、白名单字段及有界真实数据；支持 Alpha158 与因子库表达式的指定日期计算 |
| `run_strategy_backtest` | 同一 `BacktestService` 提交后台回测任务，页面和 Agent 共用报告 |
| `run_rank_analysis` / `run_factor_correlation` | 合并为 `analyze_factors`，提供分层、Rank IC/IR、衰减及相关矩阵 |
| `run_daily_screen` | `screen_factor_strategy`，使用相同信号逻辑筛选指定交易日 |
| `screen_stock_pool` | 按本人真实数据日、代码和因子条件筛选，返回代码与 as_of；不假装拥有源 MySQL 行业及历史指数成分 |
| `save_memory` | 用户明确要求后，经审批维护个人研究笔记/稳定偏好；PostgreSQL 持久化，支持读取、更新和删除，不自动收集聊天或恢复旧会话摘要引擎 |

源财务表、申万历史行业、历史指数成分和官方逐日涨跌停规则没有随着代码自动成为平台数据。目录明确返回可用范围；请求不存在的数据会报错。自定义表达式可读取真实历史价格计算值，但当前研究规格仍只接受 Alpha158，不宣称自定义因子已经进入完整回测内核。

## 唯一运行链路

`页面 / Agent → 严格规格校验 → BacktestService → 本人数据快照 → 同一研究内核 → 本人持久报告`

三种运行类型共用取数、任务、用户隔离和报告接口：

| 功能 | 本版实现 |
| --- | --- |
| 定期调仓 | 每N个数据交易日调仓，过滤、排序、方向、持仓数、目标仓位、费用与滑点 |
| 条件触发 | 间隔=0；至少一条入场条件；每天判断信号、仓位偏离带与退出 |
| 权重 | 固定因子权重 / 滚动正 Rank IC；仅用已兑现的一日收益，无正IC回退等权并记录实际值 |
| 仓位 | 按名额等权 / 按排名固定比例 / 指定因子正值比例；未分配比例留现金 |
| 退出与保护 | 字段卖出、止盈、止损、持仓峰值回撤、最长持有日、排名跌出、不卖条件 |
| 指数与择时 | 本人Tushare的沪深300/中证500/上证指数真实行情；指数入场过滤、1～3条投票、牛熊滞回与熊市仓位 |
| 股票池 | 显式代码集合与有as_of日期的历史成员快照；只取信号日以前最后一份 |
| 暂停区间 | 不交易、不冻结净值、不补调仓；仍按当天市场价格估值 |
| 因子研究 | Rank IC / IR、正IC比例、分层收益、单调性方向与r²、多空研究净值、1～N日IC衰减、因子相关矩阵 |
| 每日选股 | 指定交易日，共享回测的过滤、排序、动态权重和目标比例；零下单 |
| 策略库 | 本人保存、新建、编辑、删除、载入重跑；报告参数也能复用；前端支持JSON导入 |
| 报告 | 完整成交、逐日持仓、信号/权重/择时、未成交原因、月度汇总、曲线、分页和完整JSON导出 |
| Agent | 目录、查询真实因子、股票池筛选、回测、分析、每日筛选、任务/报告、保存/重跑/删除策略及研究笔记；研究执行和写入经人工批准中间件 |

## 删除与不再兼容

删除旧 `/api/v1/web/backtests/latest` 专用契约、旧只读Top15组件、固定收益 `strategy_backtest_service.py` 及只验证假收益的测试。没有 `dashboard.backtest` 别名、TS table.field 参数转换或演示曲线。

原模型训练/留出验证及模型搜索不是此次因子策略回测，保留不动。旧“生成Python插件”的审核路径没有新因子策略规格，明确阻断其假回测证明，不能把任意插件静态检测冒充历史业绩；本版不允许研究引擎执行用户任意代码。

## 数据和权限

- Token仍在原账户表，Alpha158仍保留五年；本人第一次写入自动建立 `stock_ud_<哈希>.backtest_run`、`backtest_strategy`，需要指数时建立 `backtest_index_cache`。不删除账号、持仓、订单或其他用户数据。
- 读取个人Alpha158的指定列、指定日期/代码，服务端游标按天流式处理；整个任务使用 PostgreSQL REPEATABLE READ 只读快照，运行中日更/清理不会改变输入。
- 策略定义按需增量建表/增列并持久化版本和运行关联；部署无需重跑数据库 baseline。既有个人策略仍可读取。审批记录绑定账号、会话、运行与精确工具参数，24小时过期；确认提交 `agent.resume` 后台任务，再创建独立研究任务。审批恢复前失败可重试，已开始执行但结果不确定时阻止自动重放。
- 单次最多10因子、1000股票、1300数据交易日、50持仓、20000笔成交。Page与Agent共享本人执行锁；后台提交还有请求UUID幂等和同用户活动任务限制。
- 报告记录完整参数、引擎/因子版本、实际输入指纹和指数来源。保存成功报告后不会被重跑同一UUID覆盖；失败/取消只在Task Runtime留状态，不保存半份成功报告。
- 明细分页在数据库完成，前端不能指定owner/schema/Token。已完成报告独立于五年因子清理，过期数据不能承诺可原样重跑。
- 指数请求只用本人Token；缺权限、额度、交易日或行情报错，不用零收益/其他用户数据替代。指数缓存按请求范围复用，扩大范围重新校验。
- Alpha158以外财务/行业MySQL表不在此平台，不能假装已迁入这些数据。历史行业或指数成员请先提供带日期的真实成员快照；没有快照时明确使用个人库股票范围，存在幸存者偏差。

## 计算口径与有意修正

- T日收盘信号T+1开盘/收盘执行；不提供使用当日收盘因子又按当日收盘成交的前视模式。末日信号不成交，期末不强制平仓。
- 平均秩百分位、稳定代码打破并列；缺因子剔除该股，全截面缺因子不误判为清仓。
- 所有交易共用费用、现金、可卖数量、100股买入整手和可选固定涨跌幅校验。先卖后买；当日新增数量锁定，补仓不锁住原有可卖持仓。
- 退出缺行情时保留指令重试，买入缺行情不追单；旧价估值标记stale，不宣称数据缺失就是停牌。
- 不卖条件占用名额并阻止单股退出；组合择时降仓优先。固定仓位总和>1归一化，<1且已填足名额时留现金；因子仓位全非正则不买。
- 暂停区间仍按市场估值，删除原仓库冻结净值的特殊口径。
- 原始OHLC配合adj_factor；复权变化按等效份额再投资近似处理，非实际分红送转到账，可能产生小数持仓。综合买卖费率是用户假设，不声称等于历年全部真实税费。
- 可选固定比例限制不是按板块/ST/新股区分的真实涨跌停；未模拟冲击、成交量参与率或退市清算。缺整个市场交易日需数据源进一步核验，不静默宣称交易所完整撮合。
- 同池等权基准为前一数据日已知成员的复权收益参考（非实际交易基金），缺个股行情沿用旧价；真实指数基准必须有数据。年化252日、无风险率0、胜率区分卖出笔与正收益日。
- 因子分析收益为收盘到下一采样收盘、等权不计费用；多空研究序列不代表可交易账户。IC/相关性缺值成对剔除，不足3只或零方差为空；IR为IC均值/样本标准差、不年化；相关矩阵按方向调整后的因子计算。

## 接口与布局

`GET /api/v1/web/backtests/catalog` → 可用字段、日期、指数和规格JSON Schema。
`POST /api/v1/web/backtests`、`/analyses`、`/screen` → `{spec, request_id, confirmed:true}`，返回Task。
`GET /api/v1/web/backtests` → 本人报告；`/{uuid}`摘要、`/{uuid}/rows`数据库分页、`/{uuid}/export`全报告；DELETE需确认。
`GET/PUT /api/v1/web/backtests/strategies` 与 DELETE `/strategies/{uuid}` → 保留既有调用，使用同一策略存储。

`GET /api/v1/web/strategies`、`GET/PUT /{uuid}`、`POST /from-report`、`POST /{uuid}/rerun`、`DELETE /{uuid}` → 新策略工作台。编辑、重跑、删除绑定预期版本；写入附带确认与请求UUID，旧策略写接口同样要求这些校验。

`backtesting/`保留既有研究内核，新增 `strategy_store` 管理版本与报告关联。前端“策略”为日常主入口，“策略研究”为参数编辑与研究报告的二级页面；共同调用同一套 Task API 和研究服务。

## 验收和部署边界

CI使用临时PostgreSQL和离线构造行情；包括可手算的现金/费用/归因、未来数据不影响过去、动态IC与择时延迟、触发再平衡、持有保护、暂停估值、缺行情退出、完整成交与持仓、分层IC/衰减/相关矩阵、用户隔离、重复提交/不可覆盖、一致性快照、因子删除后报告保留、策略库、API验证和Agent确认门。
Chromium测试使用真实构建前端和受控API夹具检查三种任务、复杂参数、策略保存编辑、明细翻页、完整导出；不是线上真实数据端到端验收。

部署使用通过测试的完整提交 SHA 和仓库现有腾讯云工作流，遵守 production 环境审批与活动任务保护。不修改 `STOCK_USER_CREDENTIAL_KEY`，不需要手动执行 baseline 或清库。首次使用前运行个人日更，在实际可用日期范围研究；指数功能需本人 Tushare 权限。

本项目仅用于机器学习、金融数据分析和项目展示，不构成投资建议，不用于实盘交易。
