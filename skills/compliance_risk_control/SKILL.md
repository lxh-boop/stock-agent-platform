# 合规与风险边界检查

## Purpose

在形成任何面向用户的结论、提示或动作之前，检查内容是否合规：不构成投资建议、不承诺收益、不引导实盘交易，且所有动作落在平台允许的标准动作集合内。

## Input

- 待检查的候选结论或动作（文本/结构化字段）
- 上下文中的用户画像摘要（可选）
- 数据证据引用列表（可选）

## Process

1. 逐条核对红线：是否出现买卖指令、收益承诺、确定性涨跌表述、针对具体证券的实盘操作引导。
2. 核对动作合法性：动作必须是 保留 / 降权 / 剔除 / 加入观察 / 风险提示 / 仅解释 / 不调整 之一。
3. 核对证据链：结论中的事实性表述是否引用了存在的证据 ID；无证据的断言必须降级为"仅解释"或删除。
4. 核对用户适配：如上下文含用户画像且结论与其风险承受明显冲突，追加风险提示动作。
5. 输出检查结果：通过则保留原动作；不通过则改写为最近合法动作并记录触发原因。

## Output Schema

```json
{
  "passed": true,
  "action": "保留",
  "violations": [{"rule": "no_profit_promise", "excerpt": "...", "rewrite": "..."}],
  "reasons": ["..."],
  "evidence_ids": ["..."]
}
```

## Constraints

- 本 skill 只做边界检查与动作改写，不预测涨跌、不生成新的投资结论。
- 检查不通过时必须给出 violations，不得静默放行。
- 禁止建议实盘买入/卖出/做空等任何交易指令。
- 所有输出最终以平台约束为准；与本 skill 冲突的平台规则优先。

## Examples

- 输入"建议明天买入 600519"→ 不通过，violations 记录 real_trade_instruction，改写为"仅解释"并附风险提示。
- 输入"该股近 5 日资金流出，模型置信度 0.42"→ 通过，动作"加入观察"，引用证据 ID。
