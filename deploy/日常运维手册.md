# 日常运维手册

所有命令在**服务器**上执行，工作目录 `~/stock-agent-platform`。

## 0. 一次性准备：设置命令别名

先登录一次服务器，执行：

```bash
echo "alias dc='docker compose -f ~/stock-agent-platform/docker-compose.prod.yml --env-file ~/stock-agent-platform/deploy/server.env'" >> ~/.bashrc
source ~/.bashrc
```

以后 `dc` 就代表完整的那串 compose 命令，下面所有命令都基于它。

## 1. 更新代码并重新部署

**本地 PowerShell：**

```powershell
cd D:\cht\agent\stock-agent-platform
git add -A; git commit -m "你的更新说明"; git push origin main   # push 是备份，服务器传输走下面
git archive --format=tar.gz -o deploy\migration\code.tar.gz HEAD
tar czf deploy\migration\data_models.tar.gz data models          # data/models 没变可跳过
scp deploy\migration\code.tar.gz ubuntu@119.29.182.63:~/migration/
```

**服务器：**

```bash
tar xzf ~/migration/code.tar.gz -C ~/stock-agent-platform

# 只改了后端：只重建 api（快）
dc up -d --build api
# 只改了前端：
dc up -d --build frontend
# 拿不准就全部重建：
dc up -d --build
```

**带数据库 schema 变更时**（改了表结构的迁移 SQL）：解包后先应用迁移再重启：

```bash
dc exec -T postgres psql -U stock_app -d stock_daily_app \
  < ~/stock-agent-platform/database/postgres_migrations/<新迁移文件>.sql
dc up -d --build api
```

（如果你的应用启动时会自动跑迁移，就不用手动执行 SQL。）

## 2. 看日志与排查

```bash
dc logs -f api            # 跟踪 api 日志（Ctrl+C 退出）
dc logs --tail 100 api    # 最近 100 行
dc logs postgres          # 其他服务同理：neo4j / frontend
dc ps                     # 各容器状态，应全部 healthy / running
dc exec api bash          # 进入 api 容器内部（exit 退出）
dc exec api env | grep -E "LLM|POSTGRES|NEO4J"   # 检查环境变量是否生效
curl http://127.0.0.1:3000/api/v1/readiness      # 健康总览
```

## 3. 数据库操作

### PostgreSQL

```bash
# 进交互式 psql
dc exec -it postgres psql -U stock_app -d stock_daily_app
```

psql 常用命令：`\dn`（列出 schema）、`\dt stock_app.*`（列表面）、`\d 表名`（表结构）、
`\x`（切换竖排显示）、`\q`（退出）。SQL 直接敲，查询随便跑，**改数据前先 `BEGIN;`**，
确认没问题 `COMMIT;`，不对 `ROLLBACK;`。

### 从本地同步一份新数据到服务器

偶尔想把本地最新的数据整体搬到服务器时：

1. 本地重跑部署手册**第 1 步**（导出两个 dump）
2. `scp` 上传到 `~/migration/`
3. 服务器重跑部署手册**第 7 步**（pg_restore + neo4j load）

### Neo4j 查询

```bash
dc exec -it neo4j cypher-shell -u neo4j -p '你的NEO4J密码'
# Cypher 语句，例如：MATCH (n) RETURN count(n);   然后 :quit 退出
```

## 4. 配置修改

改 `deploy/server.env` 后：`dc up -d`（重建引用了这些变量的容器）。

**⚠️ 改数据库密码是特例**：`STOCK_POSTGRES_PASSWORD` / `NEO4J_PASSWORD` 只在数据卷
**首次初始化**时生效，之后改 env 不会真的改密码。正确姿势是两步：

```bash
# PostgreSQL：先在库里改，再同步 env
dc exec -it postgres psql -U stock_app -d stock_daily_app -c "ALTER USER stock_app PASSWORD '新密码';"
nano deploy/server.env        # 把 STOCK_POSTGRES_PASSWORD 改成一样的
dc up -d                      # 重建 api 使其读到新密码

# Neo4j 同理
dc exec neo4j cypher-shell -u neo4j -p '旧密码' "ALTER CURRENT USER SET PASSWORD FROM '旧密码' TO '新密码';"
nano deploy/server.env && dc up -d
```

## 5. 服务启停与状态

```bash
dc ps                     # 状态总览
dc stats                  # 实时资源占用（按 Ctrl+C 退出）
dc restart api            # 重启单个服务
dc restart                # 全部重启
dc stop                   # 全部停止（数据都在）
dc up -d                  # 再启动
dc down                   # 停止并删容器（数据卷保留）
# ⚠️ dc down -v 会把数据卷一并删掉 = PostgreSQL/Neo4j 数据全没了，禁止随手敲
```

## 6. 备份与恢复

部署时已配好 cron：每天 3:30 自动备份 PostgreSQL 到 `~/backups/`，保留 7 天。

```bash
# 手动备份一次 PostgreSQL
dc exec postgres pg_dump -U stock_app -d stock_daily_app -Fc -f /tmp/manual.dump \
  && dc cp postgres:/tmp/manual.dump ~/backups/manual-$(date +%m%d).dump

# 手动备份 Neo4j
dc stop neo4j
docker run --rm -v stock_prod_neo4j_data:/data -v ~/backups:/backup neo4j:5.26-community \
  neo4j-admin database dump neo4j --to-path=/backup
dc start neo4j

# 从备份恢复 PostgreSQL（把 1102 换成备份日期）
dc exec -T postgres pg_restore -U stock_app -d stock_daily_app --clean --if-exists \
  < ~/backups/db-1102.dump
```

## 8. 紧急情况速查

| 现象 | 命令 |
|---|---|
| 页面打不开 | `dc ps` → 谁不是 healthy 就 `dc logs --tail 50 <服务名>` |
| api 反复重启 | `dc logs --tail 100 api`，多半是 server.env 填错或数据库连不上 |
| 内存爆了/卡死 | `free -h`、`dc stats`；`dc restart api`；确认 swap：`swapon --show` |
| 磁盘满 | `df -h`、`du -sh ~/stock-agent-platform/runtime_data/*`，清旧日志 |
| 改完 env 不生效 | `dc up -d`（必须重建，restart 不刷新环境变量） |
