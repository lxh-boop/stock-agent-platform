# 服务器部署手册（腾讯云轻量 4核4G3M · Ubuntu 24.04 · Docker CE）

全部命令手动执行。约定：

- 本地 = 你的 Windows（Git Bash），仓库目录 `D:\cht\agent\stock-agent-platform`
- 服务器 = 腾讯云轻量（`ssh ubuntu@<公网IP>`，用户名 ubuntu）
- 部署目标形态：4 个容器（api / postgres / neo4j / frontend），只对外暴露 3000 端口

---

## 第 0 步 · 准备

1. 拿到服务器公网 IP（轻量控制台 → 实例详情）。下面用 `<服务器IP>` 代替。
2. 本地环境是**便携版原生安装，没有 Docker**：PostgreSQL 16.9 在 `D:\cht\agent\postgres\pgsql`，
   Neo4j 5.26 在 `D:\cht\agent\neo4j\neo4j-community-5.26.0`。导出数据用原生命令，在 **PowerShell** 里执行。

## 第 1 步 · 本地导出数据（PowerShell）

```powershell
mkdir D:\cht\agent\stock-agent-platform\deploy\migration -Force

# ---------- PostgreSQL ----------
# 启动本地 pg（若已在 5432 监听会自动跳过）
powershell -ExecutionPolicy Bypass -File D:\cht\agent\postgres\start_pg.ps1

# 导出整库（含 stock_app + stock_runtime 两个 schema，自定义格式自带压缩）
$env:PGPASSWORD = (Get-Content D:\cht\agent\postgres\secrets\postgres_password.txt -Raw).Trim()
& D:\cht\agent\postgres\pgsql\bin\pg_dump.exe -h 127.0.0.1 -p 5432 -U stock_app `
  -d stock_daily_app -Fc `
  -f D:\cht\agent\stock-agent-platform\deploy\migration\stock_daily_app.dump

# ---------- Neo4j ----------
# java 路径必须在当前会话里先设好（stop 和 dump 都依赖它）
$env:JAVA_HOME = "D:\cht\agent\neo4j\jdk-21.0.12.1+1"
$env:NEO4J_JAVA_HOME = "D:\cht\agent\neo4j\jdk-21.0.12.1+1"

# Neo4j 没在运行的话，直接跳过停库这一段
if (Get-NetTCPConnection -LocalPort 7687 -State Listen -ErrorAction SilentlyContinue) {
  & D:\cht\agent\neo4j\neo4j-community-5.26.0\bin\neo4j.bat stop
  if (Get-NetTCPConnection -LocalPort 7687 -State Listen -ErrorAction SilentlyContinue) {
    Get-CimInstance Win32_Process -Filter "Name='java.exe'" |
      Where-Object { $_.CommandLine -match 'neo4j' } |
      ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
  }
}

# 导出（--to-path 是目录，产物自动命名为 neo4j.dump）
& D:\cht\agent\neo4j\neo4j-community-5.26.0\bin\neo4j-admin.bat database dump neo4j `
  --to-path=D:\cht\agent\stock-agent-platform\deploy\migration

# 导完把本地 Neo4j 启回来
powershell -ExecutionPolicy Bypass -File D:\cht\agent\neo4j\start_neo4j.ps1

# 检查产物
Get-ChildItem D:\cht\agent\stock-agent-platform\deploy\migration
```

两个文件加起来预计 1~1.5G（压缩后）。`deploy/migration/` 和 `deploy/server.env`
不要提交进 git（本手册第 2 步会加进 .gitignore）。

## 第 2 步 · 本地推送代码

```powershell
# 把迁移目录和 server.env 加进 .gitignore（追加即可）
Add-Content .gitignore "`n# 部署迁移数据与服务器密钥`ndeploy/migration/`ndeploy/server.env`nruntime_data/"

git add .gitignore
git status          # 顺便检查有没有未提交的本地改动
git add -A; git commit -m "add linux prod deployment"   # 有改动才需要
git push origin main
```

## 第 3 步 · 服务器初始化

```bash
ssh ubuntu@<服务器IP>    # 密码在站内信；首次登录后建议改掉

# 1) 4G 内存机器必备：4G swap（防 OOM 保险丝）
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swap.conf
sudo sysctl -p /etc/sysctl.d/99-swap.conf
free -h    # 应看到 Swap: 4.0Gi

# 2) 确认 docker 与 compose 插件（Docker CE 镜像自带）
docker --version && docker compose version

# 3) 建部署目录
mkdir -p ~/migration
```

## 第 4 步 · 代码上服务器 + 传数据

服务器连 GitHub 不通（国内云服务器常态），代码走 SSH 打包传输；`data/`、`models/`
在 git 里只有 .gitkeep，需要单独打包。

**本地 PowerShell：**

```powershell
cd D:\cht\agent\stock-agent-platform

# 1) 打包 git 已跟踪的全部代码（约 3~4MB）
git archive --format=tar.gz -o deploy\migration\code.tar.gz HEAD

# 2) 打包 data/ 和 models/（约 17MB，compose 要挂载这两个目录）
tar czf deploy\migration\data_models.tar.gz data models

# 3) 上传（dump + 代码包，共约 40MB，几秒钟）
scp deploy\migration\code.tar.gz deploy\migration\data_models.tar.gz deploy\migration\*.dump `
  ubuntu@<服务器IP>:~/migration/
```

**服务器：**

```bash
mkdir -p ~/stock-agent-platform
tar xzf ~/migration/code.tar.gz -C ~/stock-agent-platform
tar xzf ~/migration/data_models.tar.gz -C ~/stock-agent-platform

# 自检：三样都在就对了
ls ~/stock-agent-platform/docker-compose.prod.yml ~/stock-agent-platform/deploy/server.env.example
ls ~/stock-agent-platform/data ~/stock-agent-platform/models
```

## 第 5 步 · 服务器配置环境变量

```bash
cd ~/stock-agent-platform
mkdir -p deploy
nano deploy/server.env    # 粘贴 deploy/server.env.example 内容并修改：
```

必改三处：
1. `STOCK_POSTGRES_PASSWORD` / `NEO4J_PASSWORD` → 自己生成的强密码
2. `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` → 你实际用的外部 LLM API
   （云服务器跑不了本地 ollama，**必须**配外部 API）
3. `STOCK_AGENT_CORS_ORIGINS=http://<服务器IP>:3000`

## 第 6 步 · 构建并启动

```bash
cd ~/stock-agent-platform
docker compose -f docker-compose.prod.yml --env-file deploy/server.env up -d --build
```

- 首次构建 30~60 分钟（torch + python 依赖下载受 3M 带宽限制）。
  可选加速：在 `Dockerfile.compose` 的 `runtime-base` 的 `ENV` 块里加一行
  `PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple \`（torch 不受影响，走原有 CPU 源）。
- 看进度：`docker compose -f docker-compose.prod.yml logs -f api`，Ctrl+C 退出不影响运行。
- 就绪状态：`docker compose -f docker-compose.prod.yml ps`，等 api 和 frontend 变 healthy
  （api 的 start_period 是 90 秒，多等一会正常）。

## 第 7 步 · 恢复数据

```bash
cd ~/stock-agent-platform
DC="docker compose -f docker-compose.prod.yml --env-file deploy/server.env"

# PostgreSQL
$DC exec -T postgres pg_restore -U stock_app -d stock_daily_app --clean --if-exists \
  < ~/migration/stock_daily_app.dump

# Neo4j：必须先停容器再 load，完事再启动
$DC stop neo4j
docker run --rm -i -v stock_prod_neo4j_data:/data neo4j:5.26-community \
  neo4j-admin database load neo4j --from-stdin < ~/migration/neo4j.dump
$DC start neo4j

$DC restart api    # api 重启后重连数据库
```

## 第 8 步 · 验证

```bash
curl http://127.0.0.1:3000/healthz            # 应返回 ok
curl http://127.0.0.1:3000/api/v1/readiness   # status 应为 ready
free -h                                       # 看内存水位
docker stats --no-stream                      # 看各容器内存是否在限额内
df -h /                                       # 磁盘应还有 25G 以上
```

然后本地浏览器打开 `http://<服务器IP>:3000`，登录跑一个排名页 + 一次 agent 任务。

## 第 9 步 · 腾讯控制台放行端口

轻量控制台 → 实例 → 防火墙 → 添加规则：**TCP 3000**（来源 0.0.0.0/0）。
22 端口默认已放行。数据库 5432、Neo4j 7687、API 8010 都**不需要**放行——
浏览器走 3000，nginx 在容器网络里反代 `/api/`。

## 第 10 步 · 收尾加固与日常维护

```bash
# 1) 日志与 prompt dump 定期清理（AGENT_FLOW_TRACE=0 时 dump 很少，保险起见仍加上）
(crontab -l 2>/dev/null; echo '0 4 * * * find ~/stock-agent-platform/runtime_data -type f -mtime +30 -delete') | crontab -

# 2) 每日自动备份数据库（凌晨 3:30，保留 7 天）
(crontab -l 2>/dev/null; echo '30 3 * * * docker exec stock_prod-postgres-1 pg_dump -U stock_app -d stock_daily_app -Fc -f /tmp/db.dump && mv /tmp/db.dump ~/backups/db-$(date +\%m\%d).dump 2>/dev/null; find ~/backups -name "db-*.dump" -mtime +7 -delete 2>/dev/null') | crontab -
mkdir -p ~/backups
```

- **改密码**：实例创建时的密码已在聊天记录里出现过，控制台「重置密码」换一个；
  以后习惯用 `ssh-keygen` + `ssh-copy-id` 密钥登录。
- **看资源**：`docker stats`（实时）、`free -h`（内存+swap）、`df -h`（40G 磁盘）。
- **更新代码后重新部署**（服务器连不上 GitHub，走打包传输）：
  本地重跑第 4 步的 `git archive` + `scp` → 服务器 `tar xzf ~/migration/code.tar.gz -C ~/stock-agent-platform`
  → `docker compose -f docker-compose.prod.yml --env-file deploy/server.env up -d --build`
  （数据在 volume/挂载目录里，重建容器不丢）。想要服务器直接 `git pull` 的话，
  可以把仓库镜像一份到 Gitee，服务器从 Gitee 拉取。
- **压测前**：把 `deploy/server.env` 里 `STOCK_AGENT_MAX_CONCURRENT_TASKS` 调大
  （比如 16），`up -d` 重建 api 生效；测完改回 4。

## 常见问题

| 现象 | 处理 |
|---|---|
| api 容器反复重启 | `$DC logs api` 看报错；十有八九是 server.env 少填或密码不对 |
| readiness 一直不 ready | Neo4j/Postgres 没就绪或密码错：先看 `$DC ps` 两个库是否 healthy |
| 内存吃紧 | `docker stats` 找大户；Neo4j 可再降到 heap 192m；确认 swap 已开 |
| 磁盘涨得快 | `du -sh ~/stock-agent-platform/runtime_data/*` 找大目录，清理 cron 是否生效 |
| 页面能开但接口报错 | 浏览器 F12 看请求；确认访问的是 `http://<IP>:3000`（nginx 才会反代 /api/） |
