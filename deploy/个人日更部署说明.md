# 个人日更：普通账号可用、各自数据源、各自计划

本次只更新 chatgpt 分支。不修改账号角色，不重置密码，不重新生成加密主密钥。
Token 和模型设置仍保存于原来的 stock_app.user_account 表；新增 scheduler_config_json 保存个人计划。

## 行为变化

- 任意登录账号均可保存自己的更新时间、启停补跑、手动日更。
- 所有日更由服务端认证身份决定 owner；忽略客户端 all_users、owner_id、数据目录和 Token。
- 行情/新闻抓取使用本人的 Tushare Token；未配置或失效则明确报错，不回落服务器或其他用户 Token。
- API 与 Task Worker 都进入同一用户数据域。任务、锁、日志、RAG 索引和行情 CSV 分开保存。
- 股票排名、新闻、行情等旧表没有 user_id，使用同一个 PostgreSQL 中的 stock_ud_<账号哈希> schema 隔离。
  只复制表结构和索引，不复制公共数据。账号、原有持仓、订单和会话仍保留在 stock_app 原表。
- 模型代码/权重是共享只读资源，个人推理结果和 metrics 不写回公共模型目录。
- 旧公共数据不删除，也不会自动冒充个人数据。新用户首次日更需要建立历史数据（最长 250 日模型特征）。
- 当前实际数据源仍为仓库已有的 Tushare/AKShare 组合，并未新增其他厂商适配器。
- 旧 Streamlit 通用 operations RPC 不再对 Web 放行；当前 React 使用 web/* 与 Task API，不受影响。

## 更新部署（已有版本已运行）

1. 获取最新 chatgpt 源码，沿用已有 server.env、data、models，不上传/覆盖真实密钥。
2. 保留原 STOCK_USER_CREDENTIAL_KEY；不要生成新的，也不要清空原用户字段。
3. 在项目目录应用 005_personal_daily_schedule.sql；只增加一列：

```bash

docker compose -f docker-compose.prod.yml --env-file deploy/server.env exec -T postgres psql -v ON_ERROR_STOP=1 -U stock_app -d stock_daily_app < database/postgres_migrations/005_personal_daily_schedule.sql
```

4. 建立持久化目录并重建应用（保持上次成功的 torch 构建参数，避免重复下载依赖）：

```bash

mkdir -p runtime_data/users
```

5. 普通账号登录，确认自己的 Token 已配置，再点击“立即运行我的日更”。个人自动计划默认关闭，需自行启用保存。
6. 用第二账号验证：不能看到/覆盖第一账号的排名与日志；修改第二账号的更新时间不改变第一账号计划。

## 日志与恢复

宿主机 runtime_data/users/<用户名>/logs/scheduler/ 保存子进程 out/err 日志；
runtime_data/users/<用户名>/runtime/jobs/ 保存完整状态。容器重建不会丢这些文件。
新增 schema 自动初始化需要当前 PostgreSQL 应用角色具有建 schema/table 权限（现有 Compose 初始化角色具备）；
权限不足会明确失败，绝不回落到公共排名。
升级前已有公共排名与账号数据不删除。回滚代码无需删新增字段/schema；个人已生成的数据可保留。

本次不包含将所有 Alpha158 因子值持久化到数据库的另外一项改造。
