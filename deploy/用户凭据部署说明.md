# 多用户 Token 隔离：部署准备

本改动仅在 `chatgpt` 分支；合并 main 和重新部署前先准备加密主密钥。

## 数据存储

在现有 `stock_app.user_account` 表添加：
- `llm_config_json`：每人的非敏感 LLM 选项；
- `llm_api_key_ciphertext`：每人的 LLM API Key（Fernet 加密密文）；
- `tushare_token_ciphertext`：每人的 Tushare Token（Fernet 加密密文）。

`password_hash` 字段保持原样；不存储可逆的登录密码。
设置 API 和 Agent 都根据已认证的 user_id 读取用户专属配置，普通用户不能读写其他账号；密钥不回显到浏览器。

## 部署前（必须）

1. 在安全的 Python 环境安装 `cryptography`，执行：

   ```bash
   python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
   ```

2. 将生成的整行密钥填入服务器上 **未纳入 Git 的** `deploy/server.env`：

   ```env
   STOCK_USER_CREDENTIAL_KEY=在服务器生成的Fernet密钥
   ```

3. 将密钥单独安全备份：数据库恢复也需要同一把密钥；遗失或更换旧密钥会让已保存的用户 Token 无法解密。
4. 在服务器执行 SQL 迁移文件 `database/postgres_migrations/004_account_scoped_credentials.sql`（或让 API 启动时通过 `ensure_auth_schema()` 幂等执行同样的 ALTER TABLE）。
5. 重新构建 API 和前端；生产 Compose 已将加密主密钥注入 API 容器，未配置时保存 Token 会明确失败，不会明文落库。
6. 使用两个普通用户验证：A 保存 Token 后 B 仍显示未配置；B 保存后不影响 A；A 的 Agent 使用 A 的 Key。

## 重要边界

- 平台自动日更仍使用服务端公共数据源 Token；普通用户保存自己的 Tushare Token **不替换平台级行情下载凭据**。
- 用户 Agent 任务使用当前登录用户的 LLM Key，没有配置则明确提示，**不会自动借用全局或其他用户的 Key**。
- 更改公共日更时间和触发“完整日更”仍需管理员权限。
- 历史全局 Token 不自动复制到任何用户账户；需要本人在设置页重新填写。
- 用户可设置面向公网的 HTTPS LLM API 地址，拒绝回环/私网地址以降低 SSRF 风险。
- 如需回滚应用代码，请勿删除表新增字段；用户密文仍保留，便于之后恢复。
