# 用户凭据与个人日更部署

当前设计：每个登录账号都能管理自己的 Token、模型配置、自动更新计划并手动运行自己的日更。普通账号不需要升级为管理员。

## 原用户表继续使用

在 `stock_app.user_account` 保存：
- `password_hash`：原密码哈希，保持不变。
- `llm_config_json`：本人模型选项。
- `llm_api_key_ciphertext`、`tushare_token_ciphertext`：Fernet 加密后的本人凭据。
- `scheduler_config_json`：本人的定时时间、启停和补跑设置。

设置 API 从登录会话确定 user_id，不接受客户端指定其他账号。未配置自己的 Token 时明确报错，不自动借用服务器或其他账号的凭据。模型权重和程序代码仍为服务器共享只读资源。

## 已部署旧版时

沿用已有 `STOCK_USER_CREDENTIAL_KEY`，不要重新生成或覆盖。执行新增迁移 `005_personal_daily_schedule.sql`；建立 `runtime_data/users` 并使用最新 Compose 重建 API 与前端。完整命令、持久化说明和双账号验收见同目录 `个人日更部署说明.md`。

## 首次安装用户 Token 功能时

需先应用 `004_account_scoped_credentials.sql`（或应用认证 schema 的幂等升级），并设置加密主密钥：

```bash
# 仅在首次安装、此前未保存用户密文时生成一次；不要向聊天发送输出。
python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

将输出填写到服务器未跟踪的 `deploy/server.env` 的 `STOCK_USER_CREDENTIAL_KEY` 字段，安全备份到独立位置。数据库恢复需要同一把主密钥。缺失主密钥时拒绝保存 Token，不以明文回落。

## 数据与任务边界

各账号的行情、新闻、排名使用同一个 PostgreSQL 中的独立 `stock_ud_<账号哈希>` schema；文件缓存、RAG 索引和日志放到个人工作目录。已有账号、持仓、订单与会话保留原表，公共历史数据不删除，也不自动复制给新账号。

手动更新、自动计划均执行本人任务；旧全局日更计划不会自动变成所有人的个人计划。升级后各账号按需自行启用。当前数据源适配仍为原项目的 Tushare/AKShare，并非新增其他供应商。

历史全局 Token 不自动复制到个人账号。管理员和普通用户一样填写自己的业务凭据。服务器数据库密码与加密主密钥不开放给普通用户。

代码回滚时不要删除新增账号字段、个人 schema 或工作目录。本次个人日更改造不包含 Alpha158 因子值正式入库。
